# HSR 作品集演示 · 讲解脚本

> 配合 `HSR_Demo_Presentation.pptx`（17 页）使用。目标时长 8–10 分钟。
> 录屏建议：每页按「此页讲什么 → 画面演示 → 一句技术点」推进。
> 语气：像在带朋友逛自己的项目，讲得出"我为什么这么做"就好，不用背稿。

---

## P1 封面（~15 秒）

**讲：**
大家好，这个项目叫 HSR。我用 Unreal Engine 5.6 和 C++，从一张白纸把它搭成了一款能从头玩到尾的单机回合制 JRPG。不是拿模板改的，是我一个阶段一个阶段敲出来的。下面几分钟，我带大家把这个项目从里到外逛一遍。

（画面：停在封面，让标题读几秒。）

---

## P2 项目一句话（~35 秒）

**讲：**
一句话说清这项目：用 UE5.6 加 Gameplay Ability System，从空工程搭出「探索 → 遭遇 → 回合战斗 → 结算 → 养成 → 存档」的完整闭环。

我给自己定了三个小目标，做项目的过程中一直拿它们对表：
第一，**闭环要完整**，是真正玩得起来、有头有尾的游戏，不是一个单页的演示片；
第二，**工程要扎实**，全程走 TDD，系统之间用纯值数据打交道，权威和表现分开；
第三，**内容要原创**，正式的地图、角色、技能、遗器，全是我重新做的，没有复制任何商业作品。

（这句「不复制商业作品」对作品集挺重要，面试官常问版权，自己主动说反而是加分项。）

---

## P3 制作路线全景（~35 秒）

**讲：**
这张是完整的制作路线，从 P0 工程基线一直排到现在的 P18 正式内容整合，一共 18 个阶段。

大家看的时候留意两点。第一，**每个阶段都是能玩的**，不是写完代码就完事——比如做战斗那阶段，我当时就要求自己必须能实打实打赢一场。第二，下面这条主线是所有阶段的骨架：探索 → 遭遇 → 回合战斗 → 养成 → 存档。每推进一个阶段，其实都是往这条主链上补一环，环环咬合。

（录屏：可切游戏画面快速走一遍主线；没有就先跳过。）

---

## P4 玩法闭环总览（~45 秒）

**讲：**
这张是核心玩法闭环。从探索地图出发，撞上敌人进独立战斗地图，回合制分胜负，赢了结算经验、掉落和遗器，回到探索里用背包和遗器面板把角色养起来，最后存档，之后任何时刻读档都能接着玩。

右边是正式场景的探索画面。这里我想重点说一个贯穿全项目的设计习惯：**系统之间只传纯值数据快照，不跨地图传 Actor 引用**。这样存档、回放、自动化测试都天然安全——后面每一页，你们会看到这个习惯反复出现。

（录屏：从探索走到触发一场战斗，或者直接进战斗地图打一场。）

---

## P5 探索层（~45 秒）

**讲：**
探索层我主要做了四件事。

一是第三人称的移动、镜头和跳跃，用 Enhanced Input 做数据驱动，键位都在数据里配好，不在代码里写死。

二是交互系统，走近 NPC 或物体，屏幕会出提示，按一下 F 就交互。交互的观察层是事件驱动的，不是每帧去轮询。

三是敌人 AI，用行为树做巡逻、感知、追击，玩家跑远丢了目标，敌人会自己回巡逻点。

四是地图系统，三张正式探索地图互相连通：观景车厢、新艾丽都六分街地铁站、黑塔空间站支援舱段。地图面板是数据驱动的，按钮直接显示目标地图的中文名，想从哪张图去哪张都行。

左边是正式场景，右边是早期的灰盒版本。能看到我是先拿灰盒把玩法跑通，再上正式美术的。两张探索图上我还摆了巡逻敌人，碰上去就进战，另外放了好几个内容不一样的宝箱。

（录屏：角色走一圈，走近 NPC 看交互提示，再演示敌人发现玩家开始追。）

---

## P6 回合制战斗（核心页，~1.5 分钟）

**讲：**
这页是整个项目的心脏，回合制战斗。

上半是战斗流程：行动条按速度排序 → 玩家下指令 → 选目标 → 伤害结算 → 推进到下一回合。这里有个我很得意的点——**行动条是事件驱动的，全程没有用 Tick**。

战斗系统往下拆是这几层：
- 普攻、战技、终结技、治疗四类技能，普攻攒 SP，终结技攒能量；
- 元素弱点系统，打中弱点削韧，韧性打空触发击破，敌人行动被延后；
- 状态效果，Buff、持续伤害、免疫、驱散；
- 伤害走我自己定的公式，有暴击、防御减伤、属性克制。

右边我把一次伤害怎么算完整列了出来。这里特别想说：伤害结算是一条**纯值计算管线**，准备阶段把公式算好，应用阶段照着执行，每一步都有能追踪的分解结果。所以自动化测试能非常精确地去验证它，改数值也不会怕。

（录屏：完整打一场，边打边讲：选技能 → 选目标 → 看伤害数字 → 敌人行动 → 触发击破。这是全片最重的演示，多给点时间。）

---

## P7 养成系统（~45 秒）

**讲：**
养成这块我分三部分讲。

角色成长：等级、经验曲线、属性跟着等级走、技能等级解锁，角色详情面板能看全所有数值。

遗器系统：有套装概念，两件套和四件套分别触发效果；每件有部位、主词条、副词条，能强化。这里有个我特别在意的工程细节——**遗器的属性来源是可以倒着查的**：装上会加属性，卸下会精确还原，不是我打一个临时补丁糊弄过去。

背包和奖励：物品分类、筛选、排序，掉落和奖励走结算，重复奖励有防重保护，资源有上限保护。

（录屏：打开角色详情 → 装一件遗器看属性变化 → 卸下看还原 → 在背包里筛物品。）

---

## P8 任务与对话（~45 秒）

**讲：**
这页讲任务和对话。正式任务叫「界域回响」，流程是：观景车厢调查 → 六分街调查 → 开宝箱 → 击败巡检机 → 击败 Boss 来古士。

任务系统是事件驱动的：探索和战斗里发生的事件会推进任务目标，任务状态会进存档。对话系统支持 NPC 分支对话，对话选项能推进任务、触发遭遇、发放奖励，对话层独立于暂停菜单，体验上比较自然。

有一点我得诚实讲：当前任务数据层还不暴露标题字段，「界域回响」这个标题要出现在任务 UI 里，还需要一个后续的呈现字段任务。这是我如实记下的边界，没有藏着。

（录屏：和 NPC 对话选一个分支 → 看任务目标更新。）

---

## P9 存档系统（~1 分钟）

**讲：**
存档系统覆盖所有权威数据：角色队伍、背包遗器、任务进度、地图位置、奖励账本。

右边是可靠性设计：事务写入——先写暂存，再提交主档，最后校验；版本化 Schema 加保守迁移，旧档升级不丢数据；冷启动恢复——任何阶段读档，队伍、位置、任务、奖励全部还原；写坏了还有回退。

最核心的还是那句话：存档序列化全用纯值 DTO，**不存 Actor、Widget、GameplayEffect 的引用**。所以存档结构干净，跨版本也稳。

（录屏：进游戏做几件事 → 保存 → 退出 → 重开 → 状态完整还原。这段能直观证明存档不是摆设。）

## P10 UI 总整合（~45 秒）

**讲：**
这套 UI 是 Phase 17 统一整合的，走深色 HSR 风格。

核心是一个暂停中枢，按 Tab 或数字键打开，所有模块共用同一套输入策略、焦点导航和返回逻辑。下面八个面板：角色、队伍、背包、遗器、任务、地图、挑战、存档——每个都是独立模块，但共享同一个外壳，进出很统一。

（录屏：打开暂停中枢 → 依次进出几个面板 → 展示统一的返回逻辑和焦点移动。）

## P12 架构亮点（~1 分钟，面试重点）

**讲：**
这页是面试重点，我特意用分层图讲架构，不贴代码。

从上往下四层：
- 最上面是表现层 UI，UMG 只订阅纯值快照，不直接碰权威数据；
- 表现事件层，权威结算完会发布 Damage、Toughness、Break、Heal 这些纯值事件；
- 战斗权威层，Coordinator 是单一权威，管着 TurnManager、Targeting、Status；
- 数据层是 DataAsset 定义加纯值 DTO。

核心原则一句话：**系统之间只传纯值结构体，不传 Actor、Widget、GameplayEffect 引用**。好处是回放安全、存档安全、测试安全。整个项目都绕着这个原则转。面试要是问我为什么，我会说：这是让一套多人规模的复杂系统变得可验证的关键。

## P13 数据怎么流动（~1 分钟）

**讲：**
上一页讲的是"层"，这页讲"数据在路上是怎么走的"——一次完整的游戏循环。

最上面这条横线就是主流程：探索地图 → 遭遇 → 回合战斗 → 结算养成 → 存档。注意看，每一步之间我都是用一个**纯值结构体**在交接：探索里敌人撞上来，构造一份 `FHSREncounterRequest`；进战斗、打完了，回传一份 `FHSRBattleResult`。中间没有任何 Actor 指针跨越世界。

下面这五行是数据具体经过的边界，我挑几个说：
① 探索到遭遇，是敌人重叠触发，生成一份请求，带上队伍和遭遇 ID；
③ 战斗内部全程是纯值，`FHSRBattleParticipant`、`FHSRDamageResult` 这些，没有指针；
⑤ 最后各个子系统把自己的数据导出成一份 `FHSRSaveData` 快照，走事务写入落盘。

一句话总结这页：**权威结果永远是一份可回放、可存档、可测试的纯值数据，UI 只是它的投影。**

（录屏：可以快速切一下探索 → 战斗 → 结算的画面，配合讲。）

## P14 各子系统关系（~1 分钟）

**讲：**
这页把系统关系摊开看。左边是常驻在 GameInstance 里的数据中心：角色、队伍、装备遗器、背包、奖励、任务、地图、挑战，八个子系统各管一摊。

右边是两个关键点。第一个是**存档是唯一的汇聚点**——`UHSRSaveSubsystem` 把所有子系统的数据导出成一份快照，全部用纯值 DTO 序列化。你看这些依赖关系：奖励要依赖背包，任务要依赖奖励，装备要把属性投影到角色的 ASC，最后都在存档这里归一。

第二个是**战斗世界和探索是分开的**。`AHSRBattleGameMode` 和它的 `UHSRBattleCoordinator` 是一套独立的世界，两个世界之间只通过 `UHSRBattleTransitionSubsystem` 握手，传纯值请求和纯值结算，谁也不碰谁的内存。

这张图是我面试时最想让人看懂的：**谁拥有权威、数据在哪汇聚、边界上到底传什么**。这三句话讲清楚了，比背十个类名有用得多。

## P15 质量保障（~35 秒）

**讲：**
每个功能包都走同一套 TDD 流程：先写一个注定失败的测试 → 实现到通过 → 构建加自动化回归 → 用户 PIE 验收。

项目攒了几十个自动化测试套件，构建持续通过，十八个阶段一个一个验收过来的。工程纪律上：权威、表现、存档三个职责分离，表现层失败可以回退，不影响权威结果；用户验收过了才标记完成，证据分级记录。

（数字按实际证据讲，别夸大——面试里数据诚实比漂亮重要。）
