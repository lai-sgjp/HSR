## P1 封面（~20 秒）

**讲：**
大家好，这个项目叫 HSR，是我用 Unreal Engine 5.6 和 C++ 从零搭建的一款单机回合制 JRPG。它不是模板改的，是从空白 C++ 工程起步，一步步把探索、回合战斗、养成和存档做成了一套完整可玩的闭环。下面我用几分钟带大家过一遍。

（画面：停留在封面，等标题读完。）

## P2 项目一句话（~40 秒）

**讲：**
一句话概括这个项目——用 UE5.6 加上 Gameplay Ability System，从空白工程搭出「探索 → 遭遇 → 回合战斗 → 结算 → 养成 → 存档」的完整闭环。

我做这个项目有三个目标：
第一，**完整闭环**，是真正能从头玩到尾的游戏，不是单页的 Demo；
第二，**工程严谨**，整个开发过程走 TDD，系统之间用纯值数据传递，权威和表现分离；
第三，**原创内容**，所有正式的地图、角色、技能、遗器都是重新作者化的，不复制任何商业作品。

（这句「不复制商业作品」对作品集很重要，面试常问版权，主动说明加分。）

## P3 制作路线全景（~40 秒）

**讲：**
这张是完整的制作路线，从 P0 工程基线一路到现在的 P18 正式内容整合，一共 18 个阶段。

大家注意两点：第一，**每个阶段都是一个可玩的小闭环**，不是写完代码就完事——比如战斗阶段就做出能实际打赢一场战斗的版本。第二，下面这条主线是所有阶段的骨架：探索 → 遭遇 → 回合战斗 → 养成 → 存档，每加一个阶段，都是往这条主链上补一环。

## P4 玩法闭环总览（~50 秒）

**讲：**
这张是核心玩法闭环。从探索地图出发，遇到敌人进入独立战斗地图，回合制分胜负，胜利结算经验、掉落和遗器，回到探索后用背包和遗器面板强化角色，最后存档，任何时候读档都能继续。

右边这张是正式场景的探索画面。这里我要强调一个设计点：**系统之间只传纯值数据快照**，没有跨地图的 Actor 引用。这意味着存档、回放、自动化测试都天然安全——这是整个项目反复使用的核心原则。

（录屏：从探索走到触发一场战斗，或直接进战斗地图打一场。）

## P5 探索层（~50 秒）

**讲：**
探索层主要做四件事：
一是第三人称移动、镜头和跳跃，用 Enhanced Input 数据驱动；
二是交互系统，走近 NPC 或物体出现提示，按键交互；
三是敌人 AI，用行为树做巡逻、感知、追击，丢失目标会回到巡逻点；
四是地图系统，三张正式探索地图互通：观景车厢、新艾丽都六分街地铁站、黑塔空间站支援舱段。地图面板是数据驱动的，按钮直接显示目标地图的中文名，从任意地图都能传送去另外两张。

右边左边是正式场景（Scrapopolis），右边是早期灰盒验证版本。可以看到我是先灰盒验证玩法，再上正式美术。两张探索地图上还摆了巡逻敌人（碰触进战）和多个内容不同的宝箱。

（录屏：控制角色走一圈，走近 NPC 看交互提示，演示敌人发现玩家后追击。）

## P6 回合制战斗（核心页，~1.5 分钟）

**讲：**
这页是项目的核心，回合制战斗。

上半是战斗流程：行动条按速度排序 → 玩家下指令 → 选择目标 → 伤害结算 → 推进到下一回合。整个行动条是**事件驱动的，没有用 Tick**。

战斗系统包含几层：
- 普攻、战技、终结技、治疗四类技能，普攻攒 SP，终结技攒能量；
- 元素弱点系统，攻击弱点削韧，韧性打空触发击破，敌人行动延后；
- 状态效果，Buff、持续伤害、免疫、驱散；
- 伤害走原创公式，有暴击、防御减伤、属性克制。

右边我写了一次伤害怎么算的完整链路。这里特别想强调：伤害结算是一个**纯值计算管线**，准备阶段算好公式，应用阶段执行，每步都有可追踪的分解结果，所以自动化测试能精确验证。

（录屏：完整打一场战斗，边打边讲：选技能 → 选目标 → 看伤害数字 → 敌人行动 → 触发击破。这是全片最重要的演示，多花点时间。）

## P7 养成系统（~50 秒）

**讲：**
养成系统分三块。

角色成长：等级、经验曲线、属性随等级成长、技能等级解锁，角色详情面板可以看到完整数值。

遗器系统：有套装概念，2 件套和 4 件套分别触发效果；每件有部位、主词条、副词条，可以强化。这里有一个我在意的工程点——**遗器属性来源可逆追踪**：装上会加属性，卸下会精确还原，不是简单打个补丁。

背包和奖励：物品分类、筛选、排序，掉落和奖励结算，重复奖励有防重保护，资源有上限保护。

（录屏：打开角色详情 → 装备一件遗器看属性变化 → 卸下看还原 → 在背包里筛选物品。）

## P8 任务与对话（~50 秒）

**讲：**
这页讲任务和对话。正式任务叫「界域回响」，流程是：观景车厢调查 → 六分街调查 → 开启宝箱 → 击败巡检机 → 击败 Boss 来古士。

任务系统是事件驱动的：探索和战斗中的事件会推进任务目标，任务状态进入存档。对话系统支持 NPC 分支对话，对话选项可以推进任务、触发遭遇或发放奖励，对话层独立于暂停菜单。

需要诚实说明一点：当前任务数据层还不暴露标题字段，「界域回响」这个标题出现在任务 UI 里还需要一个后续的呈现字段任务——这是我如实记录的边界。

（录屏：和 NPC 对话选一个分支 → 看任务目标更新。）

## P9 存档系统（~1 分钟）

**讲：**
存档系统覆盖所有权威数据：角色队伍、背包遗器、任务进度、地图位置、奖励账本。

右边是可靠性设计：事务写入——先写暂存，再提交主档，最后校验；版本化 Schema 加保守迁移，旧存档升级不丢数据；冷启动恢复——任意阶段读档，队伍、位置、任务、奖励全部还原；写坏档有回退。

最关键的是：存档序列化全部用纯值 DTO，**不保存 Actor、Widget、GameplayEffect 的引用**，所以存档结构干净、跨版本稳定。

（录屏：进游戏做几件事 → 保存 → 退出 → 重新打开 → 展示状态完整恢复。这段能直观证明存档不是摆设。）

## P10 UI 总整合（~50 秒）

**讲：**
这套 UI 是 Phase 17 统一整合的成果，走的是深色 HSR 风格。

核心是一个暂停中枢，按 Tab 或数字键打开，所有模块通过同一套输入策略、焦点导航和返回逻辑接入。下面八个面板：角色、队伍、背包、遗器、任务、地图、挑战、存档——每个都是一个独立模块，但共享同一个外壳。

（录屏：打开暂停中枢 → 依次进出几个面板 → 展示统一的返回逻辑和焦点。）

## P12 架构亮点（~1 分钟，面试重点）

**讲：**
这页是面试重点，我用分层图讲架构，不放代码。

从上往下四层：
- 最上层是表现层 UI，UMG 只订阅纯值快照，不直接碰权威数据；
- 表现事件层，权威结算完成后发布 Damage、Toughness、Break、Heal 这些纯值事件；
- 战斗权威层，Coordinator 是单一权威，管 TurnManager、Targeting、Status；
- 数据层是 DataAsset 定义加纯值 DTO。

核心原则就一句话：**系统之间只传纯值结构体，不传 Actor、Widget、GameplayEffect 引用**。带来的好处是回放安全、存档安全、测试安全。整个项目都是围绕这个原则设计的，面试如果问我为什么，我会说：这是让一个多人规模的复杂系统变得可验证的关键。

## P13 质量保障（~40 秒）

**讲：**
每个功能包都走同一套 TDD 流程：先写失败的测试 → 实现到通过 → 构建加自动化回归 → 用户 PIE 验收。

项目积累了几十个自动化测试套件，构建持续通过，18 个阶段逐一验收。工程纪律上：权威、表现、存档职责分离，表现层失败可以回退而不影响权威结果；用户验收通过才标记完成，证据分级记录。

（数字按实际证据口径讲，不要夸大——面试里数据诚实比漂亮重要。）
